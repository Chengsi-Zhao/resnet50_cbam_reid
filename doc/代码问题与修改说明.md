# 旧代码问题与修改说明

本文记录项目初始实现中影响 CBAM、Re-ID 训练和 Market-1501 评测正确性的主要问题，以及目前已经完成的修改。这里的“旧代码”指本轮修复前 Git 中的实现。

## 1. 先澄清：项目不是单纯的普通分类

旧版已经同时包含以下 Re-ID 训练要素：

- 身份分类交叉熵（ID loss）；
- Batch-hard Triplet loss；
- 每个 batch 采样多个身份、每个身份多张图片的 ID-based sampler；
- Query 对 Gallery 的检索评测。

因此它不应被简单定义为“只做分类”。分类头只负责让特征具备身份判别能力；真正用于测试的是 embedding 的跨摄像头检索排序。旧版的主要问题在具体网络结构和评测协议，而不是完全缺少 Re-ID 目标。

## 2. CBAM 插入位置不符合原论文

### 原问题

旧版先执行完整的 torchvision Bottleneck，再对 Bottleneck 的最终输出使用 CBAM。由于 torchvision Bottleneck 内部已经完成：

```text
残差分支 + shortcut → ReLU
```

旧实现实际等价于：

```text
(残差分支 + shortcut → ReLU) → CBAM
```

这样注意力同时缩放了残差分支和 identity shortcut，并不是 CBAM 原论文在 ResNet 中的典型插法。

### 修改

新增 `BottleneckWithCBAM`，复用 ImageNet 预训练 Bottleneck 的卷积、BN 和 downsample 参数，并重写 forward：

```text
conv3 → bn3 → CBAM → 加 shortcut → ReLU
```

`--per_block 1` 使用上述论文式插入；`--per_block 0` 保留“stage 末尾加一次注意力”的变体，作为独立消融配置。

同时把可选范围从 layer2/3/4 扩展到 layer1/2/3/4，并支持任意组合。

## 3. BNNeck 的维度和损失分工不合理

### 原问题

旧版的顺序是：

```text
2048 维池化特征 → BatchNorm1d(2048) → Linear(2048→512)
```

分类损失和 Triplet loss 都围绕同一份线性变换后的特征工作，BNNeck 没有起到标准 Re-ID 中“分类空间与度量空间分离”的作用。

### 修改

调整为：

```text
2048 维池化特征 → Linear(2048→feat_dim) → BNNeck(feat_dim)
```

- Triplet loss 使用 BN 前的 `feat`；
- ID 分类器使用 BN 后的 `bn_feat`；
- 推理使用 L2 归一化后的 `bn_feat`。

并补充了 embedding、BNNeck 和分类头的显式初始化。

## 4. Market-1501 评测协议存在偏差

### 原问题

训练内置评测和独立评测有两套重复实现，口径并不完全一致：

1. 数据加载阶段把 Gallery 中的 pid=0 distractor 全部过滤掉，会让检索任务变简单，指标可能虚高；
2. 训练内置评测只是把“同身份、同摄像头”位置标成非匹配，却没有真正从排序序列中删除，会错误影响后续有效样本的 rank 和 AP；
3. 独立评测默认使用 `strict=False` 加载权重，结构配置不一致时可能漏载 CBAM 参数却继续给出结果；
4. 一套输出 0～1 小数，另一套输出百分数，容易误读和混用；
5. 读取损坏图片失败时用空白图片替代，会无声污染指标。

### 修改

- Query 只保留正 ID；Gallery 保留 pid=0 distractor，仅删除 pid=-1 junk；
- 排序后真正删除“同身份、同摄像头”以及 junk，再计算 CMC 和 AP；
- 训练内评测与独立评测统一复用 `compute_reid_metrics`；
- 使用分块余弦相似度计算，降低全量距离矩阵的内存压力；
- 所有 mAP 和 Rank 指标统一为百分数；
- checkpoint 自动恢复模型配置，并采用 `strict=True`；
- 损坏图片直接报错，便于定位数据问题。

标准 Market-1501 测评现在使用 3,368 张 Query 和 15,913 张 Gallery，其中 Gallery 包含 2,798 张 pid=0 distractor。

## 5. Checkpoint 信息不足

### 原问题

旧版仅保存 `model.state_dict()`。独立评测时必须人工重新填写 CBAM 层、插入方式、特征维度等参数，填错后又可能被 `strict=False` 掩盖。

### 修改

现在 checkpoint 除 `state_dict` 外还保存：

- `model_config`：CBAM 层、类型、ratio、kernel、per_block、feat_dim、dropout；
- `training_config`：学习率分组、warmup、batch、损失权重、随机种子等；
- `num_classes`、`image_size`、`epoch` 和评测指标。

独立评测默认从 checkpoint 自动恢复结构参数。

## 6. 训练日志和复现能力不足

### 原问题

- 日志累加的是未乘 `id_weight`、`triplet_weight` 的两个损失分量之和，不一定等于实际反向传播的总损失；
- 只固定了 PyTorch CPU 随机种子；
- 所有参数只能使用统一学习率，无法验证“预训练主干小学习率、注意力模块大学习率”的策略；
- 不支持 warmup；
- CBAM 只能作为完整的通道+空间组合，无法分别判断两部分作用。

### 修改

- 日志记录实际反向传播的加权总 loss；
- 同时固定 Python、NumPy、PyTorch CPU 和 CUDA 随机种子；
- 将参数分为 backbone、CBAM、Re-ID head 三组，分别支持学习率倍率；
- 增加线性 warmup 和 warmup 后分段衰减；
- 增加 `channel`、`spatial`、`cbam` 三种注意力模式；
- 增加参数合法性检查和各参数组规模输出。

消融结果也说明“功能已支持”不代表策略一定有效：主干 0.1 倍学习率在本数据和 80 epoch 配置下显著欠适配，当前应继续使用统一学习率，或把主干倍率提高后重新实验。

## 7. 实验组织与目录混杂

### 原问题

Python 源码、bash、文档、权重、日志、指标和图片都散落在项目根目录或 `runs/` 下，权重与评测结果混在同一实验目录中，不便于归档和批量处理。

### 修改

目前统一为：

```text
model/        仅保存训练权重
result/       保存评测指标、日志、曲线、PID 和报告
doc/          保存 README 之外的文档
script/       保存 Python 源码
bash_script/  保存 bash 入口
```

所有 bash 和文档中的路径已同步更新。torchvision 预训练缓存仍放在用户此前指定的 `/home/myd/data/models`，避免重复下载，也避免和项目训练权重混淆。

## 8. 已完成的消融与结果

已经完成 1 个基线和 12 个消融模型的标准评测：

- 最佳总体方案：layer2+3+4 仅通道注意力，mAP 79.7824%，Rank-1 91.7755%；
- 完整 CBAM 的最佳位置：layer3+4，mAP 78.6537%；
- 基线：mAP 77.6933%，Rank-1 91.2114%；
- 空间注意力单独使用会降低指标；
- 主干 0.1 倍学习率的分组策略明显弱于统一学习率。

完整表格、loss 曲线和分析见 `result/ablation_report/REPORT.md`。

## 9. 当前仍有的限制

- 当前结论主要来自 seed=1；正式论文建议对关键配置至少运行 3 个随机种子并报告均值和标准差；
- checkpoint 尚未保存 optimizer、学习率状态和 AMP scaler，因此还不能从中断 epoch 无缝续训；
- 当前没有 early stopping，`best_model.pth` 只在 `eval_start` 之后按 mAP 选择；
- ID sampler 对单个身份采用有放回抽样，这是常见做法，但会重复少样本身份的图像；
- 分组学习率只验证了主干 0.1 倍，尚不能据此否定 0.3～0.5 等更温和设置。
